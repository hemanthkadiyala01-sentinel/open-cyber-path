# Application Security & Bug Bounty roadmap

**Purpose:** Learn HTTP, common web-risk classes, secure design, and responsible vulnerability reporting using authorised training environments.

**Prerequisites:** Basic browser use and introductory web concepts. Begin with the request/response workbook and official training labs; do not test arbitrary public systems.

## Modules

1. **Understand the request cycle** — methods, paths, query parameters, status codes, cookies, headers, content types, and trust boundaries. Annotate the supplied benign HTTP exchange.
2. **Learn common risk classes** — access-control failures, injection, cross-site scripting, authentication weaknesses, and misconfiguration. For each, explain root cause, impact, signal, and defence.
3. **Read scope and rules** — verify assets, exclusions, permitted tests, rate limits, prohibited actions, disclosure terms, and stop conditions before research. Ask the programme owner if permission is unclear.
4. **Document responsibly** — state expected versus observed behaviour, use minimal sanitised evidence, explain impact, and suggest remediation. Avoid real user data and destructive tests.
5. **Turn research into evidence** — include reproducible steps, limitations, safe lab context, and the defensive lesson. Mark portfolio reports clearly as training-lab findings.

## Capstone

Produce a report from an official or local training lab. Include the programme/lab scope, objective, safe reproduction, expected and observed results, minimal evidence, impact reasoning, remediation, and limitations.

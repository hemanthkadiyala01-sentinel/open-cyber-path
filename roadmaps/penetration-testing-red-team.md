# Penetration Testing & Authorized Red Team

**Level:** beginner to intermediate · **Practice boundary:** owned systems, intentionally vulnerable training labs, or written permission with explicit scope only.

## Before you start

Learn TCP/IP, DNS, HTTP, Linux basics, and how to record repeatable observations. A public IP address or a bug-bounty program existing does not by itself authorise testing; read the exact scope and exclusions first.

## Learning sequence

### Module 1 — Permission and rules of engagement
Understand the difference between a local training lab, a published program scope, and an unapproved target. Study in-scope assets, exclusions, permitted methods, rate limits, privacy rules, stop conditions, and reporting channels.
**Practice:** annotate a fictional scope document and mark each scenario allowed, excluded, or needing clarification.
**Evidence:** a scope checklist that records assumptions and unanswered questions.

### Module 2 — Network and web foundations
Learn addresses, ports, DNS, HTTP request/response, cookies, sessions, authentication, and common application components.
**Practice:** label a supplied HTTP exchange worksheet; do not send probes to a real site.
**Evidence:** a request-flow diagram and vocabulary sheet.

### Module 3 — A structured assessment method
Learn asset understanding, baseline observation, low-impact verification in the provided lab, note-taking, and stopping when scope is unclear.
**Practice:** complete an assigned lesson in a deliberately vulnerable training app using its instructions.
**Evidence:** a chronological lab notebook with environment, observations, and limitations.

### Module 4 — Findings and remediation
A useful finding records affected component, preconditions, observed evidence, practical impact, severity rationale, remediation, and retest criteria. Never claim data access or impact that was not demonstrated.
**Practice:** write a fictional broken-access-control finding based on supplied evidence.
**Evidence:** a report and remediation/retest checklist.

### Module 5 — Capstone and peer review
Combine scope, safe practice, a clear finding, and a retest plan into a compact report.
**Capstone:** assess only the assigned intentionally vulnerable training application; document one supplied or safely observed issue and how to fix it.
**Deliverables:** scope note, lab journal, finding report, retest criteria, and lessons learned.

## Ready to move on when

You can explain scope boundaries, distinguish evidence from assumptions, describe why a finding matters, and propose a testable fix without touching an unapproved system.
